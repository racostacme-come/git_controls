Before you begin

Install Visual Studio 2022 with your project’s workload (for this repository: Desktop development with C++). Open the solution, then View → Git Changes and Git → Manage Branches. Sign in to your GitHub account when Visual Studio requests it. Menu wording varies by VS 2022 update and settings; use View → Terminal for commands without a UI equivalent. Replace angle-bracket placeholders before running commands.

This page simulates Git; it never reads your repository, executes commands, or uploads files. GitHub pull requests and branch protection are hosting features, not Git commands.

2. Synchronize changes with GitHub

  1. Clone or publish. For an existing GitHub repo: Git → Clone Repository. For a local project: Git → Create Git Repository → GitHub → choose owner, name and visibility → Create and Push. If origin already exists, inspect it instead of creating another remote.
  2. Start a branch. Fetch and update your base branch, then Git → New Branch. This repository currently uses master; other repositories often use main. Use the actual branch name.
  3. Edit, review, stage and commit. In Git Changes, inspect diffs, stage intended files and choose Commit Staged with a useful message. Secrets belong outside Git; .gitignore does not untrack files already committed.
  4. Fetch and inspect. Fetch downloads remote history without changing your files. Pull integrates it into your current branch. In Terminal, git pull --ff-only refuses divergent histories; if that happens, inspect the graph and deliberately merge or rebase according to your team’s policy.
  5. Integrate and test. Resolve any conflicts, finish the merge/rebase and run your project’s build and tests. This repository currently has a pre-existing C++ compilation error at line 8; synchronization does not fix that code defect.
  6. Push / Publish Branch. First CLI push: git push -u origin <branch>. Later: git push. Visual Studio may offer Sync (pull then push); review incoming work first. Push sends commits, not unsaved or uncommitted edits.
  7. Open a pull request on GitHub. Select your feature branch → Compare & pull request → choose the correct base → review diff → Create pull request. Follow reviews, checks and branch protection; merge only when authorized. Then fetch/pull the base branch locally. A pull request is separate from git pull.
Push rejected or authentication failed?

For non-fast-forward rejection, fetch and inspect incoming commits, integrate them, resolve conflicts and test before pushing. Do not use force push as a shortcut. For protected branches, push a feature branch and open a pull request. For authentication, check the remote URL, Visual Studio’s signed-in account, repository permission and organization SSO authorization. GitHub account passwords are not accepted for HTTPS Git operations; use the supported sign-in/credential manager flow. Never share a token in chat or commit it.

3. Search the command reference

Common workflows and selected advanced commands. For the complete command list installed on your machine use git help -a; for every option use git help <command>.

4. Resolve a merge conflict

  1. Git Changes lists unmerged files. Open a conflicted file in Visual Studio’s merge editor.
  2. Inspect Current (your checked-out branch), Incoming and Result. Choose or edit the intended result; accepting both is not always correct.
  3. Remove conflict markers and verify the combined behavior. Save and stage resolved files (git add <file>).
  4. For a merge, complete its commit. For a rebase, run git rebase --continue; repeat if another commit conflicts. Abort with git merge --abort or git rebase --abort if you need to reconsider.
  5. Build and test, inspect history, then push. Coordinate with teammates before rewriting any published history.
